---

## 2. Team Collaboration Rules

1. Each member should take responsibility for their assigned project area.
2. Members should communicate regularly and ask for help when needed.
3. Code should be committed and pushed to GitHub regularly.
4. Pull Requests should be used to review changes before merging into the main branch.
5. Team members should test their work before integration.
6. Database changes should be communicated to the other members.
7. All members should participate in project discussions and problem-solving.
8. The complete application should be tested together before submission.
9. Everyone should contribute to the final review and demonstration.

---

## 3. Project Communication and GitHub Workflow

- GitHub is used to store and manage the project code and documentation.
- Each member should update the team about their progress.
- Members should explain any problems that may affect other parts of the application.
- New code should be reviewed before being merged into the main branch.
- Project documentation should be updated when important changes are made.
- The team should review the overall project progress regularly.
